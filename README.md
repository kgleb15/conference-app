# conference-app

Система подачи заявок на конференцию

#### Запуск в Docker

`docker compose up --build`

- сайт: `http://localhost:3000`;
- бэкенд: `http://localhost:8080`;
- бд: `localhost:5433`.

`docker compose down` - остановить;

`docker compose down -v` - остановить и удалить данные.

##### Запуск без Docker

Бэк. В папке backend:

запуск:`./gradlew bootRun`;

сервер на `http://localhost:8080`;

тесты: `./gradlew test`.

Фронт. В папке frontend:

установка зависимостей:`npm install`

запуск: `npm run dev`;

сервер на `http://localhost:5173`.

## Основные сведения

- Все тела запросов и ответов - JSON.

- Три роли: участник, организатор, член экспертной комиссии.

- Вход - HTTP Basic: в каждом запросе заголовок Authorization: Basic. Логин - email, пароль задаётся при регистрации.

- Первый организатор создаётся при старте приложения (email, пароль и направление - в `application.properties` или в переменных окружения).

- Дедлайны (задаются в `application.properties`):

T1 . До него участнику можно подавать, редактировать и отзывать заявку. 

T2 . До него участнику можно дорабатывать заявку, которую организатор вернул.

После дедлайна подача, правка и отзыв возвращают `403`.

- У заявки 1 или 2 автора (владелец и соавтор) и 1 или 2 научных руководителя.

- Один человек может иметь не больше 2 активных заявок в одном направлении.

- Организатор и член экспертной комиссии привязаны к одному направлению и видят только его заявки.

- Ошибки валидации - `400`.
- У ответов `401`, `403`, `404`, `409` тела нет

## Статусы заявки

`SUBMITTED` - подана, ждёт решения организатора;

`WITHDRAWN` - отозвана участником;

`APPROVED` - утверждена организатором;

`REJECTED` - отклонена организатором;

`REVISION_REQUESTED` - отправлена на доработку.

`TRANSFER_PENDING` - организатор передал заявку в другое направление, ждёт принятия там.

## Переключение хранилища: память - PostgreSQL

1) По умолчанию (без Docker) данные хранятся в памяти, база данных не нужна (профиль `default`, настройки в `application-default.properties`).

2) Чтобы работать через PostgreSQL, запустите бэкенд с профилем db: `./gradlew bootRun --args="--spring.profiles.active=db"`. Перед этим поднимите PostgreSQL на `localhost:5432` и создайте базу `conference_app`
   Логин и пароль (`postgres` / `12345`) заданы в файле `application-db.properties`, при необходимости поменяйте.

3) В Docker всегда используется профиль `db`.

## Запросы

### Участник

**POST /persons** - регистрация участника

Тело: { "fullName": "...", "email": "...", "phone": "...", "password": "..." }
Ответ `201`: данные человека. `400` - поля некорректны; `409` - человек с таким email уже есть.

**GET /directions** - список направлений
`200` - массив { "id": 7, "name": "..." }

**GET /applications** - список своих заявок
`200` - массив заявок (может быть пустым)

**GET /applications/{id}** - одна своя заявка
`200` - заявка; `404` - нет такой заявки или она чужая.

**POST /applications** - подать заявку
Тело: 

```json
{
  "title": "Название",
  "annotation": "Краткая аннотация",
  "thesisText": "Текст тезисов",
  "groupName": "ПрИн-467",
  "applicantCategory": "STUDENT",
  "fundingType": "BUDGET",
  "directionId": 7,
  "supervisors": [
    { "fullName": "Петров Пётр Петрович", "workplace": "доцент каф. САОП" }
  ],
  "coAuthor": {
    "email": "coauthor@example.com",
    "groupName": "ПрИн-468",
    "fundingType": "CONTRACT"
  }
}
```
```

`201`- созданная заявка; `400` - поля некорректны (в том числе нет такого направления или соавтора); `403` - дедлайн прошёл или не участник; `409` - у автора или соавтора уже максимальное число заявок в этом направлении.

**PUT /applications/{id}** - изменить заявку.
`200` - обновлённая заявка; `400` - поля некорректны; `403` - дедлайн прошёл или не участник или вы не владелец заявки; `404` - нет или чужая; `409` - заявка отозвана или по ней уже принято решение или передаётся в другое направление.

**PATCH /applications/{id}/withdraw** - отозвать заявку.
`200` - заявка со статусом WITHDRAWN; `403` - дедлайн прошёл или не участник; `404` - нет или чужая; `409` - по заявке уже принято решение (утверждена или отклонена).
Повторный отзыв тоже вернёт `200`

**GET /persons/me** - данные того, кто вошёл. `200` - данные человека; `401` - неверный email или пароль.

### Организатор / эксперт

**POST /persons/organizer** - регистрация организатора

**POST /persons/expert** - регистрация члена экспертной комиссии

`201` - данные человека; `400` - поля некорректны или нет такого направления; `403` - не организатор; `409` - email уже занят.

**GET /organizer/applications** - заявки всех участников (с данными автора)
Необязательные фильтры:

- `status` - `SUBMITTED`, `WITHDRAWN`, `APPROVED`, `REJECTED` или `REVISION_REQUESTED`

- `edited=true` - только изменённые, `edited=false` - только не менявшиеся

`200` - массив заявок; `403` - не организатор.

**PATCH /organizer/applications/{id}/approve** - утвердить заявку. 

**PATCH /organizer/applications/{id}/reject** - отклонить заявку. 

**PATCH /organizer/applications/{id}/request-revision** - отправить на доработку. 

Для `reject` и `request-revision` тело: { "comment": "..." } (комментарий обязателен). Решение возможно только по заявке в статусе `SUBMITTED`. `200` - заявка с новым статусом; `400` - нет комментария; `401` - пользователь не найден; `403` - не организатор; `404` - нет такой заявки (или она из другого направления); `409` - решение уже нельзя принять (заявка не SUBMITTED).

#### Передача заявки в другое направление

Передать можно только заявку в статусе `SUBMITTED`. 

**PATCH /organizer/applications/{id}/transfer** - передать заявку.
Заявка получает статус `TRANSFER_PENDING` и остаётся в своём направлении, пока её не приняли. Пока она передаётся, решение по ней принять и редактировать её нельзя, отозвать можно.
`200` - заявка; `400` - нет такого направления; `403` - не организатор; `404` - нет такой заявки; `409` - заявку нельзя передать или у автора уже 2 заявки в том направлении.

**GET /organizer/applications/incoming** - заявки, которые передали в направление организатора. `200` - массив заявок; `403` - не организатор.

**PATCH /organizer/applications/{id}/accept-transfer** - принять переданную заявку
`200` - заявка; `403` - не организатор; `404` - заявка не передана в ваше направление; `409` - у автора уже 2 заявки в вашем направлении.

**PATCH /organizer/applications/{id}/decline-transfer** - отклонить передачу. `200`; `404` - заявка не передана в ваше направление.

**PATCH /organizer/applications/{id}/cancel-transfer** - отменить передачу своей заявки, пока её не приняли. `200`; `404` - нет такой заявки в вашем направлении; `409` - заявка не передаётся.

#### Эксперт

**GET /expert/applications** - список утверждённых заявок
`200` - массив заявок (может быть пустым); `401` - нет входа; `403` - не эксперт.

**GET /expert/applications/{id}** - одна утверждённая заявка
`200` - заявка; `404` - нет такой заявки или она не утверждена; `401` - нет входа; `403` - не эксперт.

## Фронтенд

Вход - по email и паролю (Basic). Данные входа и сведения о пользователе хранятся в sessionStorage до закрытия вкладки. После входа открывается страница роли, слева показывается меню.

Страницы:

- `/` - главная, 

- `/login` - вход, 

- `/register` - регистрация участника; 

- участник: `/submit` - подача заявки, `/my` - мои заявки (изменение и отзыв); 

- организатор: `/moderation` - модерация заявок, `/add-expert` - добавление эксперта; `/add-organizer` - добавление организатора

- эксперт: `/review` - утверждённые заявки без данных автора.
